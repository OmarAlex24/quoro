# Spike init config format (v0)

The pipeline (`oci2rootfs`) writes `/quoro/config` into the rootfs and copies the
init binary to `/quoro/init`. The kernel boots with `init=/quoro/init`. The init
reads `/quoro/config` after mounting `/proc`, `/sys` and `/dev`.

Format: UTF-8, one `key=value` per line, split on the first `=`. Lines starting
with `#` and empty lines are ignored. Values never contain a newline (the
pipeline refuses to write one). Unknown keys are a fatal config error.

| Key | Repeat | Meaning |
| --- | --- | --- |
| `arg` | 1+ | argv of the app, in order; `arg[0]` is the program (absolute path, or resolved against the app's `PATH`) |
| `env` | 0+ | one `NAME=VALUE` environment entry |
| `uid` | 1 | numeric user id the app runs as |
| `gid` | 1 | numeric primary group id |
| `workdir` | 1 | absolute working directory (default `/` if the image sets none) |
| `hostname` | 0-1 | hostname to set |

Example:

```
# generated by oci2rootfs from docker.io/library/alpine@sha256:...
arg=/bin/sh
arg=-c
arg=echo hello from alpine; cat /etc/alpine-release
env=PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
uid=0
gid=0
workdir=/
hostname=spike
```

## Console protocol (what the init prints)

- Serial (`/dev/ttyS0`, the kernel console; `console=ttyS0`): init diagnostics and
  markers, each line prefixed `quoro-init: `.
  - `quoro-init: QUORO_SPIKE_BOOT_OK uptime_ms=<guest uptime in ms from /proc/uptime>` once the
    config is parsed and mounts are done, just before the app starts. This is
    the marker the spike waits for.
  - `quoro-init: QUORO_SPIKE_APP_EXIT code=<n>` (or `signal=<n>`) when the app exits.
  - `quoro-init: FATAL <message>` on any boot failure, then power off.
- virtio-console (`/dev/hvc0`): the app's output, one line per app line, tagged
  `out ` or `err ` (the tag, one space, then the line as written). A trailing
  partial line is flushed at EOF.
